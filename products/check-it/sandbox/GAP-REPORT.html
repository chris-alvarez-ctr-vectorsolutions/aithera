Design System Gap Report — v4 Prototype

Vector Web Components v1.5.1 · Prepared 2026-06-29 · For the Vector design-system team + CheckIt product leadership

What this is: the high-level effort read and recommendations, plus — for every genuine design-system gap — a live render of the UI element next to its gap analysis. Elements render using the prototype's real CSS (dark-only colors swapped for the prototype's own light-theme values), so what you see matches the prototype on a production light background.

Companion docs: EFFORT-SUMMARY.md · ADJUDICATION-WORKSHEET.md · DEDUP-SWEEP.md · expansion-matrix.md

The headline

Supporting the v4 prototype's fidelity is at most ~197 design-system person-days — but that is a pre-adjudication ceiling that assumes every callout is a real, independent gap. It isn't. A consistency sweep found that ~77% of the prototype's ~214 distinct custom-pattern implementations are the same pattern reimplemented under different class names (the prototype was built without design-system validation). The apparent surface is ~214 treatments; it collapses to ~27 real components.

The realistic design-system build is small. After adjudication, only ~19 callouts are genuine design-system gaps, and they skew small — mostly themes, slots, and recipes, plus a handful of clean net-new primitives. Everything else is prototype cleanup (your team), straight adoption of shipped components, or product-layer work that shouldn't be design-system-costed at all.
