## Summary

The SafeLMS Reports workspace with async report generation: Run Report starts a
background job, the admin can opt into an email, and finished runs are kept in
the Report Log for viewing and export. V1 is what dev is building against
(`dev_handoff.html`).

**V2 is a post-handoff change from beta feedback.** In the V1 Report Log you
can't tell runs apart. Each row shows only the report type, and View Report
opens with the filters back at their defaults, so the parameters only show up
in the download. V2 adds the following:

- **Report name.** On Run Report, the run is saved to the Report Log under a
  default name: the report type plus that type's run number (for example
  "Completions by Employee 10"). Each report type counts up on its own. The
  generating banner says so by name. Rows have no pencil: the name is edited
  in the row's **Report Details** modal. Saving it blank brings back the
  default name.
- **Search and filters on the Report Log.** These are styled like the live
  SafeLMS controls: "Label **Value** ⌄" filter buttons on the left and a white
  pill search with the magnifier on the right. There's no report count. The
  search box matches the name,
  default name, type, date range, generated date, person, and every setting
  value. **Report type** and **Status** filters narrow it further, and no
  matches shows "Clear search and filters". The pencil banner that sat on top
  of the log is removed.
- **The table matches the live Report Log.** The card is padded around the
  table, the header is a rounded gray-blue band, rows are compact, and status
  is plain text ("Ready" / "In Progress"). The column and button are named
  **Download** (navy, with the Excel/CSV menu), and View Report is a bold navy
  link.
- **Generating state matches the live build.** The spinner is replaced by the
  light-blue banner from the current product ("Your report request has been
  saved to the Report Log … and is currently generating.") with Email Me The
  Report and a dismiss ✕, above the generated row at 0 results.
- **Email Me The Report asks for a title.** The button opens a small modal with
  a Report title field already filled in with the default name (report type + run number). Email Me
  saves the title as the run's name and requests the email. The blue banner
  is then replaced in place by the live build's white confirmation banner
  (green accent + check, dismiss ✕): "We'll email you when **<title>** is
  ready." 
- **Date Range column.** All four async reports (Compliance by Employee,
  Completions by Employee, Completions by Time, Training Compliance) take a date
  range.
- **Report Details modal on every row.** Each row has a chevron on the right
  and no pencil. Clicking anywhere on a row, except Download and View Report,
  outlines it in blue (like the live employee list) and opens a **Report
  Details** modal styled like the live employee modal:
  - a header with the name, the type and a round close
  - an editable **Report Name** with a green **Save** (renaming happens here)
  - the report settings (values the admin changed are bold, defaults gray)
  - Generated / Generated by / Status
  - **View Report** (tertiary text button) and **Download** (primary, on the
    right). Both are hidden while the run is In Progress.

  The drawer pattern that was tried on the top rows is removed.
- **View Report restores the run.** The report opens with its date range and
  filters set to what the run used (changed filters highlighted), under a "From
  the Report Log" header with the name, run details, and Back to Report Log.
- **Generated date means finished.** **Generated** is when the report
  finished. It shows "—" in the log and "Generating…" under the banner until
  then (the live build stamps "Generated" at request time). A separate Run date
  was tried and dropped.
- **One value per column, with no secondary lines of copy.** The Report Log
  columns are Report name · Report type · Date range · Generated ·
  Generated by · Status · Download · View Report, plus the open chevron.
  Below about 1360px the cells
  wrap. If the table still doesn't fit (at about 1024px), the card scrolls
  sideways and the page doesn't. Export menus open as fixed popovers so the
  scrolling card can't clip them.

## Open questions (V2)

- **Default-name numbering.** The mock numbers runs per report type. Does
  the count run per site or per admin, and does it ever reset?
- **Name limits.** The mock caps names at 100 characters. Confirm the limit, and
  whether duplicate names are allowed (the mock allows them).
- **Who can rename.** Is it only the admin who ran the report, or any admin who
  can see the log?
- **Is the name the export filename?** Should the CSV/Excel file be named after
  the report?
- **Parameter list per report.** The details row uses the mock's shared filter
  set plus Positions/Locations. Each report's real parameter list (for example
  the email-address toggle on Compliance by Employee) should drive what's shown.
- **Re-running from a saved report.** In the mock, Run Report on a reopened
  report runs again with the restored settings and logs a new row. Confirm this
  is intended.
