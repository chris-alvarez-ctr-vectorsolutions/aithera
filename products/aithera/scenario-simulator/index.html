Scenario Simulator

Two things live here: the example interactions the dev team builds V1 against, and the editor an LXD uses to produce the JSON their engine runs.

Start here

Play an example The universal player, running the go-forward format. Every pattern below is the same player with a different scenario. Open the editor Author a new scenario from a template, or Import JSON to edit an existing one. Export gives you the file to upload back.

Example interactions

One per interaction pattern, all on the same player. These are the UX and interaction reference — that part is the source of truth for V1. The content inside them is not: it is demonstration material, and it does not need to match what ships.

  • Universal scenario — the go-forward format, composed from coach, roleplay and observe steps
  • Composed arc — coach-led, roleplay and observe beats in one scenario
  • Guided arc — learn then practise, one topic at a time
  • Branching ladder — the scene escalates or de-escalates on what the learner says
  • Ensemble — several characters, disclosure earned across phases
  • Observe & spot — canvas — find the hazards in a photo
  • Observe & spot — text log — the same scenario, findings typed instead of clicked
  • Teach-back — the learner explains it back, the coach grades the retrieval
  • Roleplay conversation — a single hard conversation, rehearsed line by line

Authoring

The editor targets the production engine's schema. A new scenario starts from one of the built-in templates; an existing one arrives as its .lo.json file.

  • Editor — current — the build to use for real work
  • Editor — prototype — experimental UI; separate drafts, nothing here reaches the current build until it is released
  • Release notes & promotion policy — what changed, and how a change reaches the current build

The loop: open a scenario's .lo.json with Import JSON, edit it, then Export and upload the file back into the system. The export is checked against the production loader's own rules before you download it.
