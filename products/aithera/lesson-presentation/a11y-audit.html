A code-level review of all 16 prototypes in products/aithera/lesson-presentation: what each one uses (video, AI chat, drag, TTS…), the main compliance concerns, how hard each is to remediate, and what to change. Review tooling (toolbox, flow map, version switchers) was excluded.

The headline

The good news: the difficulty is not where you'd expect. The AI chat experiments are largely fine — every scripted chat that uses the shared thread is already announced to screen readers, and typed input is inherently accessible. The real cost centers are (1) the muted-video-plus-timed-captions pattern (captions run on their own timers, don't pause with the video, and have no track or transcript), (2) pointer-only mechanics that gate progression (story highlighting is a hard keyboard blocker), and (3) the coach-conversation experiments never announcing the actual dialogue — screen-reader users hear "your coach noticed something" but never what the coach said. Live (unscripted) AI raises the difficulty a tier wherever it's enabled.

Two hard blockers

Everything else degrades the experience; these two prevent completion outright for some users.

Story highlighting locks out keyboard users Blocker

In With story intro, the only way to create a highlight is drag-selecting text with a pointer, and the Continue button stays disabled until at least one highlight exists. A keyboard-only or switch user can never leave the story screen. Needs an alternate selection model (e.g., per-sentence toggle marks) — a design change, not a markup fix. 2.1.1 · 2.5.7

Live AI's main nav is invisible to screen readers Blocker

In Live AI, the Learn/Practice mode toggle is authored with aria-hidden="true" and the show/hide logic only ever toggles a CSS class — so the primary navigation stays hidden from assistive tech for the whole session, while its buttons remain in the Tab order (an ARIA anti-pattern). One-line fix, severe impact. 4.1.2 · 1.3.1

Fix once, fix (almost) everywhere

Six issues live in the shared layer (css/lesson.css, js/lesson.js, and copy-pasted patterns). Fixing them centrally clears findings across most of the set before touching any individual experiment.

1 · No prefers-reduced-motion in shared CSS

lesson.css has zero reduced-motion rules, so typing dots, flips, glows, shimmers, count-ups and scroll cues run for everyone. The four big coach experiments handle it inline — the other twelve inherit nothing. One global block fixes most of it. 2.3.3

Affects ~12 experiments via lesson.css

2 · Contrast tokens fail across the board

--ink-faint #9ca3af is ~2.6:1 on white and is used for real text (hints, ranges, eyebrows) everywhere; white-on-teal button labels (--accent) are ~3.2:1. Darkening two tokens and switching labels to --accent-strong clears dozens of instances. The coach experiments' own faint tokens (#8b94a8, #8d8175) have the same problem. 1.4.3

Affects nearly every experiment

3 · Shared chat/dialog panels don't manage focus

Lesson.chat opens as a role="dialog" but never traps Tab, never restores focus to the trigger on close, and leaves the page behind fully tabbable (even when full-bleed on mobile). Lesson.modal restores focus but doesn't trap either. 2.4.3 · 4.1.2

Fix in js/lesson.js — clears findings in every chat-equipped page

4 · Dialogue and state changes aren't announced

The shared chat thread is a live region (good), but the four coach experiments inject conversation into non-live containers, and nearly every page updates its #instructions footer text silently. Pattern fix: make instruction/status areas aria-live="polite" and mirror injected dialogue into a live region with speaker prefixes. 4.1.3

Worst in the 4 coach experiments; minor everywhere else

5 · Fake radio groups (three copies)

Quick Question, Peer Results, and the BAC calculator all declare role="radiogroup"/role="radio" but wire only click — no arrow keys, no roving tabindex. Screen readers announce behavior that doesn't exist. Use one shared implementation or native <input type="radio">. 4.1.2 · 2.1.1

3 experiments, same bug

6 · Missing <h1> / heading outline

All four coach experiments, Hazmat, and Audio Summary have no <h1> anywhere — titles are styled <span>/<p> elements. Screen-reader users get no document outline. Trivial per file. 1.3.1 · 2.4.6

Observe / React: Hazmat Size-Up

hazmat-scene-practice.htmlVery High
3 muted videostimed captionsscripted AI coachfree-text inputfull-screen takeoverresults modal

Why Very High: the core modality — silent video narrated by independently-timed caption chunks, shown in an unskippable full-screen takeover — is fundamentally hard to make conformant. It needs real caption tracks, transcripts, synchronized pause, and a skip path, on top of a long list of markup fixes.

Main concerns

  • Captions are JS timers, not a <track>: pausing the video does not pause the captions, chunks display 1.7–5.2s with no way to slow or replay, and there's no transcript. Since videos are muted, this text is the only narration. 1.2.1 · 1.2.2 · 2.2.1
  • First watch of each segment is an unskippable full-viewport takeover with no alternative for users who can't watch. 2.2.1
  • All videos share one generic label ("Hazmat scene video"); no persistent scene description for non-visual users. 1.1.1
  • No <h1>/<h2> in the document; results modal opens without moving focus and has no Escape; Escape is remapped to a mode switch. 1.3.1 · 2.4.3
  • White caption text sits on a 42%-black pill over arbitrary video frames — contrast isn't guaranteed. 1.4.3

Quick wins

  • Add <h1>; distinct per-video labels; focus + Escape for results modal; darken caption pill to ~70% black; add a Skip control

Structural

  • Real WebVTT captions + transcript; pause captions with the video; persistent scene descriptions independent of playback timing
