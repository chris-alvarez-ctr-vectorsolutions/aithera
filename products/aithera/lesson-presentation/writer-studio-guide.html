Scenario Simulator · Part 3 — The Authoring Tool

Inside Writer Studio

The first two documents describe the system — the end-to-end flow and the interaction modes. This one describes the tool an author uses to produce a scenario for that system. Writer Studio turns plain-language fields into the compiled prompts, guardrails, and published scenario the learner page runs — never raw prompt text, and never anything that can break the runtime. This is a walkthrough of how it actually works today.

Companion to the Build & Authoring Specification and The Interaction Layer.

1

What the tool is for

Writer Studio exists because authoring an AI conversation is a different act than authoring a multiple-choice item. In an MCQ you spell out every path a learner can take. In a scenario you can’t — the learner types anything and the model improvises. The author’s job moves from scripting every answer to setting the structure the model performs inside. The studio is where that structure gets written, in plain-language fields, and compiled into the artifacts the system defines.

The old craft

One stem, one right answer, three distractors

You control every option a learner can pick. Nothing happens that you didn’t type.

→

Authoring here

A situation, an answer key, and guardrails

You describe what “good” looks like and what must happen. The model plays it out live — differently for every learner, inside the frame you set.

The craft carries over — the studio names the mapping as you go. Distractors become “what a weak answer looks like.” Per-answer feedback becomes a believable character reaction. SME teaching points become the guaranteed playbook. Each field group carries a small from your old craft label pointing back to the MCQ equivalent, so the move from one craft to the other is explicit, not implied.
2

The workspace

One screen, three panes, and a top bar. The left rail is the authoring spine — the same shape a learner walks through. The center is the form for whatever section you’re in. The right is the Inspector — a live, honest view of what your fields become. Nothing here is a separate export step: what you type on the left is compiled on the right as you type.

Context and Debrief work the same across every mode; only the Interaction section is reshaped by the mode you pick.

0

Start — what are you building?

The first decision shapes every field that follows. You choose one of four core interactions (the mode), then fill the basics.

Choose the core interaction

Four cards: Roleplay, Guided Arc, Observe / React, Teach-Back. This is the only choice that changes Section ②; the studio then asks for exactly what that shape needs (§4).

Basics

Scenario title (shown in the learner’s top bar), course context (grounds the model’s register), who the learner plays, the character they talk to, spoken scene lines (target pacing), and practice length.

How is the context set?

ENTER

A source decision that ties the scenario into a course: set it in this scenario (pick an intro in the next step) or use the previous learning object — inherit the context and hand off from whatever ran right before. This is what lets a scenario sit inside the course-delivery frame rather than always cold-opening itself.

1

Scenario Context

How the scene is set before the interaction begins. One chosen intro modality, delivered by the shared context player — the same field the system spec calls intro.type.

Intro & opening

ENTER

Pick one of five: video cold open, narrated audio (listen or read), reading — text only, a written story the learner highlights, or no intro — straight in. The chosen modality reveals only its own fields (e.g. video adds per-scene URL + caption). The coach’s opening reflection rides on top of it — surfaced in-context, never a pass/fail gate.

2

Interaction — the core loop

ENTER → (ENGAGE · REACT · COACH) ×N ↺ GATE → EXIT. Shown here in Roleplay; the field groups below are the studio’s Roleplay form, each tagged with the loop phase it drives. Other modes present a different set (§4).

Character card

REACT
replaces per-answer feedback

The one artifact that drives every character reply: the situation (who they are, what happened, what’s true now — ending with who they are underneath), a when → then reaction map, and style rules the model must never cross.

Assessment dimensions

COACH
right answers & distractors

2–4 things each line is silently scored on — name, what strong looks like, what weak looks like (your distractors). They steer the character and aim the coach at the weakest dimension. Never shown to the learner as a rubric.

Misconceptions

COACH

Wrong beliefs to surface and disprove: the scene plays the consequence, the coach names it.

Coach voice

COACH

Who the coach is (a stance, not a script) and how it works — length, techniques, example questions. It probes and reflects; it never grades out loud.

The gate

GATE
the passing criterion

Hard or soft is the author’s choice. Hard blocks until the required move happens; soft nudges, then advances. You set the requirement, what does not count (the loophole), the skill sequence, a first (open) and second (concrete) nudge, and the minimum acceptable answer after two nudges — the floor the engine will honestly accept so a learner is never trapped.

Completion & handoff

EXIT

What ends the loop (usually: passed the gate plus one more observable move) and an example line of the resolution sounding believable. The results ride this final turn into the debrief.

3

Debrief & Close

Results, the guaranteed takeaways, reference material, and the read-only engine. This is the most guardrail-dense section — and where the studio surfaces what’s locked.

How results are scored

EXIT

A separate evaluation engine — not the in-scene coach — scores the session against your assessment dimensions and returns up to 3 strengths and 2 growth areas, each quoting the learner’s own words. Keeping evaluation separate from coaching is what keeps the verdict consistent across every mode.

Playbook

TAKEAWAYS
your SME-validated teaching points

Guaranteed takeaways every learner leaves with — identical for all, never AI-generated. Each is a “move” plus why it works, landing better with a short quoted example than with theory.

Resources & the crisis floor

TAKEAWAYS

Real, world-specific places the character could go (campus counseling, an EAP, a safety officer). Flagging a scenario elevated stakes automatically appends a locked crisis floor — e.g. the 988 Suicide & Crisis Lifeline — that the author can’t remove.

Reference material

GROUNDING

Paste policy or standard excerpts the model must treat as authoritative — where they conflict with its own knowledge, the pasted text wins. Attaching references compiles in a grounding rule (see §6).

System guardrails

LOCKED

The engine that makes a scenario safe to hand to a model — read-only, but readable in full: output contract, off-script input, learner safety, and reference-grounding rules, each with a “read the exact locked text.” You can see everything the runtime enforces; you can’t edit it (§6).

4

The mode reshapes Section ②

Picking a mode in Start swaps the Interaction form for that mode’s field set — Context and Debrief are unchanged. Below is what each mode asks you to author; the Interaction Layer doc has the full schema and prompt breakdown for each.

Roleplay · action-practice

Rehearse a hard conversation

The learner speaks to a model-voiced character one line at a time while the coach reads each exchange and nudges. Scoring is silent — the conversation is the point.

Section ② asks for: a character card, silent dimensions, misconceptions, coach voice, a gate, and a completion line.
ENGAGE→REACT→COACH→GATE

Example: intervening for a friend (Kendra).

Guided Arc · guided-arc

Walk a scripted arc, then reflect

The coach walks the learner through authored beats it delivers verbatim — a reflection, a knowledge check with a right answer — then a moment to react to. No role-play.

Section ② asks for: an ordered beat sequence (reflect · knowledge-check · decide), each beat authored in place.
COACH→ENGAGE→COACH→EXIT

Example: bystander intervention (Marshall).

Observe / React · observe-react

Review footage, one beat at a time

The learner reviews footage in segments and the coach probes what they saw — asking first, then validating or correcting, ending on a synthesis. No role-play.

Section ② asks for: a media segment spine, scripted openers, dimensions, and an opening question.
ENGAGE→REACT→GATE→EXIT

Example: hazmat scene size-up (I-65 tanker).

Teach-Back · teach-back

Explain it back from memory

The learner teaches required topics in their own words while a live grader tracks coverage. Here the score is the point.

Section ② asks for: a topic list (with synonyms), calibration, grading rules, and a close. Compiles to three prompts.
ENTER→ENGAGE→REACT→RESULTS

Example: applying HazCom (Teach Me).

New modes are added by registering a new scenario type against the same contract — not by improvising per scenario. The studio shell reads only a mode’s public surface and holds no knowledge of any specific pedagogy, so authors’ workflow is identical whichever mode they pick.
5

The Inspector — no black box

The right pane is the studio’s honesty guarantee. It shows exactly what your fields become, checks them, and lets you run them — three tabs, always in sync with the current draft.

Tab 1

Compiled prompt

The full system prompt your fields produce — the situation, output contract, scenario, dimensions and gate, all assembled. A char and token count sits at the top; Copy lifts the whole thing. Dynamic (authored) text reads against the locked engine sections so you always see which is which.

~2,150 tokensCopydynamic vs locked
Tab 2

Guardrails

A live lint — a spellcheck for scenarios. It flags gaps as you type: warnings are advice, blocking issues stop a broken publish. The tab shows a running count, and the header reads “All checks pass — publish when the playtest holds up” when you’re clear.

warningsblocking✓ all pass
Tab 3

Playtest

Run the current draft against the live model without publishing — the same Cloudflare Worker proxy the learner page uses. One-click stress tests load canned adversarial inputs to probe the guardrails fast.

🧨 Troll it🕵️ Break character🫂 Vague warmth⚡ Confrontation✅ Names real help
Models, made explicit. The Playtest names the model it runs — conversation and evaluation use claude-opus-4-8; Teach-Back’s fast coverage grading uses claude-haiku-4-5. Same proxy, same message shape as production, so a playtest that holds up is a real signal.
6

What’s locked, and why

The boundary between authoring and runtime is the whole point of the tool: an author writes a scenario’s content in plain language and cannot touch the pieces that keep it safe and parseable. Those pieces are visible in the Debrief section — readable, never editable.

The read-only engine sections

  • Output contract. The strict JSON shape every model turn must return. The page can render nothing else, so this can’t be loosened.
  • Off-script input. How trolling, gibberish, and jailbreak attempts are absorbed without shaming the learner.
  • Learner safety. The highest-priority rule: a learner disclosing their own crisis suspends the exercise and surfaces real help — it supersedes everything the author wrote.
  • Reference grounding. Compiled in whenever reference material is attached: pasted documents are treated as facts to build on, never as instructions that can override the rules above.
Prompt count is the platform’s call, not the author’s. Most modes compile to one prompt; Teach-Back splits into three (calibrate · grade · close). Authors never manage this — the studio compiles the extra prompts and wires them, and can surface them for reference. The elevated-stakes crisis floor is locked the same way: opt in, and the safety line is appended for you.

From draft to learner

The path a scenario takes through the studio. Draft, published, and shipped are distinct states — the learner page reads the published slot, and publishing is a deliberate act, never an autosave side effect.

01Pick a mode

Choose the Section-② shape by the skill you’re assessing.

02Fill the spine

Start → Context → Interaction → Debrief, in plain language, ✓ per group.

03Clear the guardrails

Work the lint down until nothing is blocking.

04Playtest

Run the draft against the live model; hit the stress tests.

05Publish & preview

Push to the prototype, open Learner preview, come back to adjust.
