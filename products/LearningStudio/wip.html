Searchable dropdown — with "Add new item"

Type to filter. The "Add new item" action is always pinned to the top of the list.

Claude DS Usage Notes

Built with plain HTML / CSS / JS, not vaadin-combo-box. Deliberate divergence from the design system — flagged here so it's visible.

Why custom instead of vaadin-combo-box:

  • Pinned "Add new item" action. vaadin-combo-box has no clean slot for a sticky action row that survives filtering. Forcing it through the renderer API requires excluding a synthetic option from filter, sort, and selection logic — more workaround than the custom render function it replaces.
  • Custom empty state. Vaadin's built-in "No items found" message is hard to restyle. The empty state here is a specific design (title + sub + the "Add new" action still available).
  • Filter highlighting. Bolded substring on matches isn't a Vaadin built-in.

Where the design system IS followed:

  • Font: Open Sans via Vector assets CDN
  • Icons: Font Awesome (fa-chevron-down, fa-plus) per CLAUDE.md
  • Colors: Vector blue #0066cc for focus/primary accents; the project's standard neutral grays
  • Input visuals: 36px height, 4px radius, 1px border — mimics vaadin-text-field theme="outlined" so it sits next to real Vaadin fields without looking foreign
  • Focus ring: 2px rgba(0,102,204,0.15) halo — same pattern Vaadin outlined inputs use

Handoff note for devs:

The visual mimics vaadin-combo-box theme="outlined"; it isn't using it. The "Add new" + custom-empty-state pattern is the real spec. In product code this should either (a) be rebuilt on top of vaadin-combo-box via its renderer API, or (b) prompt a request for a new Vector component if the pattern shows up in more than one place.
